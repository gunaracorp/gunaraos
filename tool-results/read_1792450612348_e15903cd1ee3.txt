    49→### ✨ 1. Tentang GUNARA OS
    50→
    51→**GUNARA OS** bukan sekadar aplikasi catatan. Ia adalah **sistem operasi lengkap untuk hidup dan bisnis** — dibangun sekelas Notion, tetapi diarsitekuri di sekeliling *satu orang*: Gugun Gunara, pemilik Gunara Corp. Setiap piksel, setiap tabel database, dan setiap animasi dirancang untuk menjawab satu pertanyaan: *"apa yang harus saya kerjakan hari ini supaya 10 tahun ke depan saya menang?"* Dokumen-dokumen strategi pribadi (14 file dari `github-docs/`) tidak dibiarkan menganggur sebagai teks — semuanya dikompilasi menjadi perangkat lunak yang hidup dan berinteraksi.
    52→
    53→Aplikasi ini menggabungkan tiga dunia yang biasanya terpisah: **OS pribadi** (filosofi hidup, disiplin harian, keuangan keluarga), **kantor konsultan perizinan** (CRM, tracker pengurusan izin ISO, katalog 46 layanan), dan **arsenal strategis** (43 domain portfolio, 15 AI agents dengan prompt role-activation siap pakai, roadmap 90 hari). Ketiganya berteistur dalam satu SPA ringkas dengan satu Command Center sebagai kokpit.
    54→
    55→Tiga keunggulan yang membuatnya berbeda:
    56→
    57→| 🏛️ | 🛡️ | ⚡ |
    58→|---|---|---|
    59→| **Arsitektur Hulu → Mesin → Hilir** | **Keamanan kelas enterprise** | **Pengalaman premium** |
    60→| Filosofi air: isi hulu sekali, mesin dirawat mingguan, hilir dijalankan harian | scrypt, AES-256-GCM, secrets di-strip otomatis dari API | Animasi sinematik penuh, ⌘K, dark mode, jam WIB live |

    65→### 🌊 2. Filosofi Arsitektur: Hulu · Mesin · Hilir
    66→
    67→Sistem ini meniru aliran sungai. **Hulu** adalah mata air — piagam diri, visi 10 tahun, OKR, dan kurikulum yang *diisi sekali* lalu menjadi sumber segala keputusan. **Mesin** adalah lima generator nilai — keuangan, CRM, relasi & politik, belajar, dokumentasi — yang *dirawat setiap minggu* agar terus menghasilkan. **Hilir** adalah aliran harian — ritual pagi, review mingguan, backlog, dan log keputusan — yang *dijalankan setiap hari* tanpa perlu berpikir ulang. Bisnis Hub berdiri di muara: tempat semua nilai mengalir menjadi pendapatan nyata.

   121→### 💎 4. Fitur Utama
   122→
   123→#### 🏠 Command Center
   124→- **Jam live WIB + sapaan dinamis** — pagi/siang/sore/malam mengikuti waktu nyata, dirender client-safe tanpa hydration error.
   125→- **3 MIT (Most Important Tasks)** — tulis, centang dengan animasi spring, otomatis sinkron dengan Ritual Harian.
   126→- **Slider energi 1–10** — angka pop beranimasi; nilai ≤ 4 memicu peringatan protokol hari buruk.
   127→- **4 stat card CountUp** — sisa hutang, piutang, klien aktif, follow-up telat; semua beranimasi dari nilai sebelumnya.
   128→- **Strip Bisnis Hub** — ringkasan pelanggan, izin berjalan, dan nilai pipeline (Rp) yang bisa diklik menuju tracker.
   129→
   130→#### 🏃 Mesin Disiplin
   131→- **Keuangan 4-in-1** — hutang dengan dialog *Cicil* (sisa terhitung otomatis + toast), piutang, arus kas, rekening anak.
   132→- **CRM cerdas** — counter pipeline, flag **TELAT** merah otomatis untuk follow-up melewati jatuh tempo.
   133→- **Ritual Harian** — MIT pagi + refleksi malam dalam satu log per tanggal (upsert otomatis).
   134→
   135→#### 🛡️ Arsenal Strategis
   136→- **15 AI Agents** — kartu per gelombang, dialog *Role Activation* berisi prompt lengkap, tombol copy → "Tersalin!".
   137→- **43 Domain Portfolio** — tabel editable + grid tergrup per tier (INTI / GATEWAY / FUTURE / PARKED).
   138→- **Roadmap Grand Build** — Fase 0–5 dengan gerbang kelulusan, kalender 90 hari, target finansial.
   139→
   140→#### 💼 Bisnis Hub — Perangkat Konsultan Perizinan
   141→- **Database Pelanggan 360°** — 25 field metadata: KTP, NPWP, alamat, sumber lead, preferensi komunikasi, status, catatan.
   142→- **Database Perusahaan** — NIB, NPWP, SK AHU, KBLI, modal, status grup (Gunara Consultant ⇄ PusatPerizinan.com).
   143→- **Kanban Perizinan 5 Tahap (ISO 9001:2015)** — Konsultasi → Dokumen → Pengajuan → Terbit → Serah Terima; status pelanggan ikut berganti otomatis saat kartu pindah tahap.
   144→- **Pencari Izin (Rules Engine)** — pilih 10 sektor × skala usaha × 9 flag kondisi → daftar izin terprioritas WAJIB → OPSIONAL + estimasi biaya + **1 klik masuk tracker**.
   145→- **Katalog 46 Layanan** — harga, durasi, instansi penanggung jawab; searchable real-time.
   146→- **Brankas Kredensial (11 kategori)** — EMAIL_GOOGLE, OSS, PAJAK, BANK, dsb.; semua terenkripsi AES-256-GCM dengan *Vault Health Check* bergaya OWASP.
   147→- **Aset Sosial Media** — platform, username, metrik follower, cadance konten, status akses.
   148→- **Pengguna & Role** — OWNER/ADMIN/STAFF dengan password scrypt + indikator kekuatan sandi NIST.

   199→<a name="id-keamanan"></a>
   200→### 🔐 7. Keamanan — Zero-Compromise Vault
   201→
   202→Keamanan dirancang dengan prinsip *assume breach*: meski database bocor, kredensial tetap terlindungi.
   203→
   204→| Lapisan | Mekanisme | Standar Acuan |
   205→|---|---|---|
   206→| Password pengguna | **scrypt** + salt unik, verifikasi *timing-safe* | NIST SP 800-63B |
   207→| Kredensial brankas | **AES-256-GCM** terenkripsi *at-rest* (password, PIN, backup codes) | OWASP |
   208→| Eksposur API | Semua field rahasia **di-strip otomatis** dari setiap response list/detail | Privacy by Design |
   209→| Reveal on-demand | Endpoint eksklusif `?reveal=password\|pin\|backupCodes` per item | Least Privilege |
   210→| Kekuatan sandi | `passwordStrength()` — panjang, variasi karakter, pola umum | NIST SP 800-63B |
   211→| Vault Health | Pemindaian kesehatan: 2FA belum aktif, sandi duplikat/lemah, cadance cadangan | OWASP AMM |
   212→| Manajemen kunci | `GUNARA_VAULT_KEY` via environment — tak pernah masuk kode | 12-Factor Config |
   213→
   214→<details>
   215→<summary>🔐 <b>Buka: alur enkripsi (diagram)</b></summary>
   216→
   217→```mermaid
   218→flowchart LR
   219→    P["✍️ Input rahasia<br/>(password/PIN/codes)"] --> E["🔐 AES-256-GCM<br/>encrypt + IV unik"]
   220→    E --> DB[("💾 SQLite<br/>ciphertext only")]
   221→    DB --> S["📦 GET /api/data/*<br/>secrets di-strip"]
   222→    S --> U["🖥️ UI: row terkunci"]
   223→    DB -.->|"GET ?reveal=password<br/>endpoint eksklusif"| R["🔓 Reveal on-demand<br/>+ audit row"]

   230→### 🌍 8. Standar Internasional yang Diterapkan
   231→
   232→| Standar | Penerapan Konkret di Kode |
   233→|---|---|
   234→| **ISO 9001:2015** | Alur perizinan 5 tahap dengan status otomatis antar-tahap — proses terukur, terdokumentasi, ter-audit |
   235→| **NIST SP 800-63B** | Kebijakan sandi + hashing scrypt timing-safe |
   236→| **OWASP Top 10 / AMM** | Enkripsi at-rest, strip secrets, Vault Health |
   237→| **WCAG 2.2** | `focus-visible` ring, dukungan `prefers-reduced-motion` (CSS + Framer), `aria-label` penuh, `sr-only` dialog descriptions |
   238→| **12-Factor App** | Konfigurasi via environment, satu codebase, proses stateless |
   239→| **SemVer** | vMAJOR.MINOR.PATCH + changelog terstruktur (lih. Riwayat Versi) |
   240→| **Clean Architecture** | UI *config-driven* dari satu peta (`gunara.tsx`), API generik, pustaka animasi terpusat (`motion.tsx`) |
   241→| **Type-Safe End-to-End** | TypeScript 5 + Prisma Client yang digenerate dari schema |
   242→
   243→Doktrin rekayasa: ** hydration-safe by design** (semua data waktu dirender client-only via `useMounted()`/`useNow()`), **reduced-motion first**, dan **lint 0 error · 0 warning** sebagai gerbang merge.

   248→### 🚀 9. Memulai
   249→
   250→**Prasyarat:** [Bun](https://bun.sh) ≥ 1.1 *(atau Node.js ≥ 20)* · Git
   251→
   252→```bash
   253→# 1️⃣ Kloning & masuk
   254→git clone https://github.com/prabudanling/doc-gunaracorp.git gunara-os
   255→cd gunara-os
   256→
   257→# 2️⃣ Instal dependensi
   258→bun install            # atau: npm install
   259→
   260→# 3️⃣ Siapkan environment — buat file .env:
   261→#    DATABASE_URL="file:./db/custom.db"
   262→#    GUNARA_VAULT_KEY="ganti-dengan-kunci-rahasia-minimal-32-karakter"
   263→
   264→# 4️⃣ Bentuk struktur database dari 26 model
   265→bun run db:push
   266→
   267→# 5️⃣ Isi data awal (idempoten — aman dijalankan ulang)
   268→bun scripts/seed.ts         # OS: piagam, visi, OKR, 43 domain, 15 agents, dst.
   269→bun scripts/seed-bisnis.ts  # Bisnis Hub: 46 layanan, 2 perusahaan, OWNER, contoh data
   270→
   271→# 6️⃣ Nyalakan
   272→bun run dev
   273→# → buka http://localhost:3000 — selamat datang di kokpitmu 🚀
   274→```
   275→
   276→> 💡 **Produksi:** `bun run build` lalu `bun run start` (standalone server). Wajib set `GUNARA_VAULT_KEY` yang kuat dan acak — kunci ini mengenkripsi seluruh brankas kredensial.

   393→### ❓ 15. FAQ
   394→
   395→<details>
   396→<summary><b>Kenapa hanya satu route (<code>/</code>)?</b></summary>
   397→
   398→Sesuai whitepaper & prinsip sandbox: satu SPA state-based lebih cepat, bebas reload, dan seluruh 19 section dilompati via Command Palette — pengalaman ala aplikasi desktop di browser.
   399→</details>
   400→
   401→<details>
   402→<summary><b>Apakah data saya aman di SQLite lokal?</b></summary>
   403→
   404→Ya untuk skenario personal: password pengguna di-hash scrypt, seluruh kredensial brankas terenkripsi AES-256-GCM, dan API tidak pernah mengembalikan field rahasia. Untuk multi-device, migrasi ke PostgreSQL + RLS sudah masuk roadmap v4.0.
   405→</details>
   406→
   407→<details>
   408→<summary><b>Kenapa jam/tanggal baru muncul setelah halaman terbuka?</b></summary>
   409→
   410→Itu fitur, bukan bug — *hydration-safe by design*. Data waktu memang hanya dirender di klien agar server (UTC) tidak pernah bertabrakan dengan klien (WIB). Nol hydration error terverifikasi.
   411→</details>
   412→
   413→<details>
   414→<summary><b>Bagaimana menambah jenis data baru?</b></summary>
   415→
   416→Tambahkan model di `schema.prisma` → `bun run db:push` → daftarkan di `MODELS` (API) + konfigurasi resource di `gunara.tsx` → section muncul. Tidak perlu endpoint baru; API-nya generik.
   417→</details>

   596→### 🔐 7. Security — The Zero-Compromise Vault
   597→
   598→Security follows an *assume breach* principle: even if the database leaks, credentials stay protected.
   599→
   600→| Layer | Mechanism | Reference Standard |
   601→|---|---|---|
   602→| User passwords | **scrypt** + unique salt, timing-safe verification | NIST SP 800-63B |
   603→| Vault credentials | **AES-256-GCM** encrypted at-rest (password, PIN, backup codes) | OWASP |
   604→| API exposure | All secret fields **auto-stripped** from every list/detail response | Privacy by Design |
   605→| On-demand reveal | Exclusive per-item endpoint `?reveal=password\|pin\|backupCodes` | Least Privilege |
   606→| Password strength | `passwordStrength()` — length, character variety, common patterns | NIST SP 800-63B |
   607→| Vault Health | Health scan: missing 2FA, duplicate/weak passwords, backup cadence | OWASP AMM |
   608→| Key management | `GUNARA_VAULT_KEY` via environment — never in code | 12-Factor Config |
   609→
   610→<details>
   611→<summary>🔐 <b>Open: encryption flow (diagram)</b></summary>
   612→
   613→```mermaid
   614→flowchart LR
   615→    P["✍️ Secret input<br/>(password/PIN/codes)"] --> E["🔐 AES-256-GCM<br/>encrypt + unique IV"]
   616→    E --> DB[("💾 SQLite<br/>ciphertext only")]
   617→    DB --> S["📦 GET /api/data/*<br/>secrets stripped"]
   618→    S --> U["🖥️ UI: locked row"]
   619→    DB -.->|"GET ?reveal=password<br/>exclusive endpoint"| R["🔓 On-demand reveal<br/>+ audited row"]
   620→```

   639→Engineering doctrine: **hydration-safe by design** (all time-based data renders client-only via `useMounted()`/`useNow()`), **reduced-motion first**, and **0 errors · 0 warnings lint** as the merge gate.

   788→<a name="en-faq"></a>
   789→### ❓ 15. FAQ
   790→
   791→<details>
   792→<summary><b>Why is there only one route (<code>/</code>)?</b></summary>
   793→
   794→By design, per the whitepaper & sandbox principle: a single state-based SPA is faster, reload-free, and all 19 sections are reachable through the Command Palette — a desktop-app experience inside the browser.
   795→</details>
   796→
   797→<details>
   798→<summary><b>Is my data safe in local SQLite?</b></summary>
   799→
   800→Yes for the personal scenario: user passwords are scrypt-hashed, all vault credentials are AES-256-GCM encrypted, and the API never returns secret fields. For multi-device, the PostgreSQL + RLS migration is on the v4.0 roadmap.
   801→</details>
   802→
   803→<details>
   804→<summary><b>Why does the clock/date only appear after the page opens?</b></summary>
   805→
   806→That is a feature, not a bug — *hydration-safe by design*. Time-based data intentionally renders on the client only, so the server (UTC) can never disagree with the client (WIB). Zero hydration errors, verified.
   807→</details>
   808→
   809→<details>
   810→<summary><b>How do I add a new type of data?</b></summary>
   811→
   812→Add a model to `schema.prisma` → `bun run db:push` → register it in `MODELS` (API) + the resource config in `gunara.tsx` → the section appears. No new endpoints needed; the API is generic.
   813→</details>
